# Grill me 專案版

這是本專案自訂的訪談技能，並非已取得或驗證的第三方同名 skill。若使用者指定其他來源，先讀取該版本，再沿用工作流的紀錄格式；不得宣稱已使用未讀取的 skill。

## 輸入與執行

1. 接收 task 目錄、角色（PM / SA / DEV / TEST）、當前交付物及要釐清的議題。缺少 task 時依使用者任務建立 `spaces/<task-slug>/`，不可把使用者字串直接當任意檔案路徑。
2. 先讀 `request.md`、`status.md`、上游交付物與本角色既有紀錄。先從文件與程式找答案，不要問使用者已能查證的問題。
3. 找出最影響正確性的未決假設，逐題追問。每題說明影響，提出具體選項及建議；依回答再追問，不一次丟出大份問卷。
4. 文件已回答的問題直接記錄出處。AI 可提出方案，但回答來源必須標 `AI_PROPOSAL`，不能寫成使用者答覆。必要的使用者決策未回答時標 `OPEN`，保存紀錄並等待；繼續不依賴該答案的工作。
5. 可逆且不影響驗收的實作細節可由角色決定，標 `ROLE_DECISION`，寫出簡短理由。只有明確得到使用者答覆才標 `USER_CONFIRMED`。無人值守不等於可自動確認。
6. 每取得答案、變更決策或發現阻礙就更新 `<role>/grill-me.md`，不要只在聊天裡提問，亦不要等全部做完才補寫。
7. 關閉本輪時列出已解決與仍開放的問題、對交付物的影響、證據連結及交接判定。提問數依議題而定，不為湊數製造問題。

## 紀錄格式

角色使用小寫路徑，例如 `spaces/cloud-file-manager/pm/grill-me.md`。保留舊輪次；以 R1、R2 等追加修訂，勿覆寫歷史。

每輪記錄：時間（含時區）、角色、skill 路徑、所讀輸入、目標交付物。
每題記錄：

- 問題 ID（例如 PM-Q001）與問題。
- 為何影響驗收、有哪些可行選項。
- 已知證據與檔案位置。
- 回答與來源：`SOURCE` / `USER_CONFIRMED` / `ROLE_DECISION` / `AI_PROPOSAL` / `OPEN`。
- 決策、簡短理由與受影響檔案。
- 狀態：`RESOLVED` 或 `OPEN`；後續負責角色。

紀錄可查證的操作、結論與精簡理由，不要求或儲存模型私有思考過程。沒有執行的工具、測試或獨立審查不得記為已完成。
