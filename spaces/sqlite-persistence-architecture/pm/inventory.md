# Read-only implementation inventory
- Domain actual names: DirectoryNode, WordFile, ImageFile, TextFile (not WordFileNode etc.). Id is initialized Guid.NewGuid, getter only; Parent/name/metadata immutable; Children readonly. Restoration of persisted identities requires a proposed controlled hydration boundary, not setters/reflection or Prototype cloning.
- NodeSnapshot intentionally produces new IDs for Paste; excludes source identity. Preserve its meaning, do not equate persistence snapshot with Prototype.
- EditingSession mutates live objects and commits undo/redo stacks immediately; failed persistence cannot be repaired by naive public Undo (Redo clearing, revision and history differ). Transaction design needs to cover state and history together, not merely wrap SQL in transaction.
- Existing schema uses TPH kind Directory/Word/Image/Text, parent Directory composite FK, sibling name uniqueness, one-root-at-most index, metadata checks and fixed Tag catalog. Missing sibling ordinal and schema version. A valid single connected acyclic tree and exactly one Root must be validated on load; date/id strings currently weakly constrained. Domain int metadata upper bounds need loader validation. SQLite text trim semantics differ from .NET whitespace validation; do not claim schema alone equals Domain validation.
- FullPath/Extension/Directory capacity derived; not separate durable columns. XmlAlias matters to legacy XML and must not be accidentally dropped.
- Web bootstrap currently resets ReferenceTree; Console resets SampleTree (Bonus adds Bonus_Copies). Shared vs separate DB and demo behavior need explicit lifecycle policy before SA final design.
- Existing WebWorkspace Gate serializes one workspace; it does not by itself coordinate external DB writers or multiple processes. Preserve classic Singleton and TASK010 consumer abstraction.
- Existing SQL/tests/history are read-only inputs. No .NET SQLite package chosen or installed. No persistence implemented.
